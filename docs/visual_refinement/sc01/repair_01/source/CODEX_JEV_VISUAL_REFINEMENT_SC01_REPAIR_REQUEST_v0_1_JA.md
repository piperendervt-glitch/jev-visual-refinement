### 4.1 修正中も維持する意味

一候補は一lane・一Kのマスク一式です。主採用は **同一ComparisonContext／有効Q／Q>=3／利用可能な候補**だけから選び、先着適格を採用、後着上位で改訂、下位・同点は現採用維持です。現採用なしの再構築は契約の固定順とします。A/R/I/C、モデル名、帯、到着予定、描画順を隠れた重みや同点破りに使いません。

当時の`delta_to_previous`と現在の`delta_to_current`は別です。根拠版が違えばdeltaはnullです。E1で最初に受理した値をE0の高得点と競わせません。有効Qを診断軸・他laneの完了まで待たせません。非採用をjob取消し・記録削除へ転用しません。

同候補の新版更新をREFRESH_SAMEとして残すことと、「異版のQで勝敗を決めないこと」は両立させます。旧fallbackに表示対象がある間は、新winnerがまだないことだけを理由に消さず、新版終端で採用なしが成立すれば契約どおりCLEARします。

### 4.2 レビューを満たすための誤った近道を避ける

- 表の文字だけ直す、queueへ見栄えのよい数を渡す、履歴を起動前に作り終える、常時ドットを流す処置では完了にしません。
- 「同じSQLite接続で読めた」ことをcommit済みの証明にしません。短い同期区間・整合した読取りsnapshot等で公開境界を守り、重いI/O・画像生成・通信をwriter lockへ押し込まないでください。
- 原画とmaskを別々に表示しただけの結果を、元座標に重畳した証拠にしません。最小の合成重畳と、そのframe・座標の対応を確認します。空maskには塗りつぶし対象を作りません。
- 終了threadをdaemon化して放置したり、強制killでlistenerを消したりしただけで正常終了としません。サービス停止とrunの業務成功は別判定です。
- 旧runの不足データ、存在しないJev理由、未観測の画面receiptを後から合成しません。

## 5．実装の進め方

**記録・状態 → 保存・公開 → HTTP → 最小UI → 検証と終了**の依存順でまとめて修正します。個々の段を別の新チャットへ切り分けることを既定にしません。

最初に対象コードと元テストを照合し、SRごとの実原因・既存テストの検査範囲を短く記録します。その後、意味を満たすために必要な型／validator／DDL／job経路／投影を補います。物理table・fileを一型一個へ強制せず、基礎Q選抜・有効な保護・rollback等の動いている部分は維持します。

UIは、利用者が画面を開いた後にfixture完了通知を進められる入口を持たせます。仮想clock・明示的なfixture制御でよく、通常のデータ経路とは別にDOMを書き換えて成功を演出しません。fixture制御はモデル／スレッド編集UIでも、実APIでもありません。

新規run作成、保存run閲覧、当時cursor Replayを入口と内部状態で区別します。修正にDDL変更が必要なら実装側の保存版・互換性を記録し、古い不十分なrunは理由付きで読取り扱いにします。旧runを完全互換に見せるために不足の記録を捏造することも、旧run原本の破壊的移行も不要です。

契約の記述に真の矛盾が見つかった場合は、該当節・最小反例・影響CFを記録し、その部分だけ判断待ちにします。実装上の通常の分割・命名・内部構造まで一件ずつ質問せず、自律的に修正してください。v0.5の意味・受入基準を修正実装に合わせて緩めません。

## 8．実ブラウザー確認と証拠

backend試験、実HTTP、JS模擬DOM、実ブラウザーを別々に報告します。模擬DOMやbackendで作ったreceiptを実ブラウザーPASSにしません。

実ブラウザーでは少なくとも、**接続後のA暫定→S改訂、B閲覧中の新しい主採用、明示復帰、E1待機の旧根拠表示、commit順の過去閲覧、画像成功／失敗とreceipt、queue増減**を確認します。必要な段階をfixtureの完了通知で制御し、単に最終表にA→Sという文字があることでは代替しません。

AとSの両方の描画を証明する検査では各表示を確認できるよう完了通知を段階解放します。別の高速到着検査では、Sだけ描画されたならAをskipped/未確認として記録してよく、全Revisionを強制描画するために選抜や本番処理を遅らせません。

receiptは画像readyと最新render、source revision自身のseqへ対応し、snapshot seqとは別です。主画像の表示、送信成功、server保存を分けます。可視を人間が実際に見た保証へ拡張しません。HTTP検査用の偽receiptは専用fixtureの否定試験にだけ使い、受入用の可視証拠へ含めません。

ブラウザー手段が使えない場合は、権限回避や無断installをせず、可能な修正・自動試験・安全な保存を完了します。そのうえで該当受入を未確認とし、SC01全項目PASSや受入完了を宣言しません。
