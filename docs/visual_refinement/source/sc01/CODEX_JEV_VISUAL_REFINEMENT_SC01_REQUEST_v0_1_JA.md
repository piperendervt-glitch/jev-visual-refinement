### 4.1 選抜で変更してはいけない意味

一候補は一lane・一Kのマスク一式です。主採用は `segmentation_q_selection_v1` に従い、**有効Q、同じComparisonContext、採用下限3、利用可能な候補**だけから選びます。最初の適格結果で暫定採用し、同contextの後着上位で改訂、下位では維持、同点は現採用を維持します。現採用なしの再構築時の固定順も別紙第8節どおりです。

A/R/I/Cを合算した総合点、コストによる同点破り、モデル名・帯・描画順による固定winnerは作りません。有効Qを診断軸の完了まで待たせません。0、欠測、無効、通信失敗、正常0maskを区別します。

低Qや非採用は、処理中止・データ削除を意味しません。非採用・維持もSelectionDecisionに残し、主表示の変更だけをSelectionRevisionとします。「当時の比較差」と「現在の採用候補との差」を別に保持します。

E1ではE0のwinnerを現contextから外し、stale_fallbackであることを示します。旧winnerと必要な対立候補を新版で再評価し、異版Qの差を算出しません。新版で最初の適格結果を表示し、遅い旧応答で戻しません。新版の終端で適格候補がなければ採用なしを示します。同候補の根拠更新はREFRESH_SAMEです。

### 4.2 記録・キューで変更してはいけない意味

完了通知は要求順に待たず、検査後にwriterへ届いたcommit順を保存します。重い画像生成・検査・通信を選抜transaction内へ置きません。評価受理・Decision・必要なRevision・状態・outboxは原子的に保存し、重複配送やretryで採用を二重化しません。

queueはunitとscopeを持ち、job・論理suite・HTTP attempt・mask枚数を混ぜません。受付前拒否・依存待ち・開始後の資源待ちも区別します。`queued=0`なら最古待機はnull、長い実行はlongest_active、情報停止はhealthで示します。計数不変式とfixture閾値は別紙第10節に従います。

候補・根拠・記録は不変とし、UI選択・queue snapshot・ACKを新しい画像根拠として再評価しません。ACK保存から新Revisionや無限ACKを発生させません。

機械可読schema・公開型の位置を明示し、後続adapterが同じ契約へ接続できるようにします。資料の保存先・再利用pathなどの実装上の局所選択と、未確認の外部仕様を混ぜません。

生成run、DB/WAL/SHM、cache、一時artifact、venv、秘密はGit対象外です。再生成可能な非機微fixture定義や専用テストはソースとして管理できます。必要な画面証拠・生ログは新側の証拠領域へ置き、索引と要約を残します。

SC00成果物の原記録を変更せず、新しい事実状態の所在を現行索引から辿れるようにしてください。手元の作業状態を旧HANDOFFへ混ぜてSC00の記録時点を失わせないでください。

試験・最小画面確認・終了確認を行い、静的整合も確認した後、今回の対象pathを明示してstageし、新repoだけにローカルcommitしてください。無関係な差分や`.env`を巻き込む一括追加を避けます。Git identity・署名・権限が不足する場合は人物情報やglobal設定を勝手に作らず、可能な成果を保存してcommit未完了を明示します。remote設定・fetch/pull/push・GitHub操作は行いません。

一回でまとめるとは一つの作業単位を閉じることであり、一つのGitコマンドしか使えないという意味ではありません。ただし他機能を混ぜません。文書が自分自身を含む最終commit SHAを循環参照するようなamendを繰り返さず、**最終提出HEADは最後の応答で確定**してください。

## 8．止める条件と、止めずに進める範囲

| 状況 | 対応 |
|---|---|
| 適用権限不足、誤repo、無関係な変更の保全不能、主要契約の欠落/内容違い | 該当書込み・実行を止め、確認事実と必要判断をまとめる。reset・再コピー・権限変更で回避しない |
| 新規依存・モデル・外部通信が必要になった | 今回の範囲へ追加しない。標準ライブラリ等で成立する範囲を進め、必要性と阻害項目を一括報告 |
| 保存容量・所有root・loopbackの安全な境界が確認できない | 影響する実行を止める。既存データの削除や元root使用で解消しない |
| ブラウザー確認手段がない | UI未確認を明示。backend試験を実UIの証拠にしない。安全に実施できる残りはまとめる |
| 実モデルのライセンス、weight、実GPU互換、Jev料金/保持が未確定 | SC01のfixtureを止める理由にしない。SC02〜04の未決として保持 |
| CFの失敗・局所バグ | 同チャットで修正と影響回帰まで閉じる。仕様変更や未承認範囲へ拡張しない |

追加判断が本当に必要な場合は、その都度小分けにせず、影響する項目・理由・最小の判断をまとめます。失敗を隠したり、単に一回で終えるために未確認をPASSへ変えたりしません。
