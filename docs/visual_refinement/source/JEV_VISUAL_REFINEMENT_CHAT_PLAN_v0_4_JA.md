**第一ゴールは「領域分割の比較・選抜アプリ」。** 同じ保存動画のキーフレームに3〜4個のセグメンターを並行投入し、完成順にJev評価、評価完了順に暫定採用・後着改訂、元フレームへマスク一式を重畳する。構成を変えて反復し、全runを後に比較できる。

本書は担当範囲と参照先だけを示す。**Codexへの依頼文・実行プロンプトではなく、作成・取得・外部送信・実装の許可を含まない。** ユーザーの明示許可まで依頼文は作成しない。旧Codex依頼は使用対象外。

## 1．短い共通境界

| 項目 | 全単位に共通すること |
|---|---|
| 独立性 | 新側は`C:\dev\jev-visual-refinement`。元会話repo・マップ改善に書き戻さない。新旧のGit・設定・保存・終了対象を共有しない |
| 入力 | 同じKの実PTS/sample/pixel hash。全フレーム追跡はしない |
| 候補 | 一経路・一Kのマスク一式。一式を混成採用しない。S/A/B/Cは未実測の編成ラベル |
| 非同期 | 解析も評価も完了順。最初の適格評価で表示し、他経路の全件待ちはしない |
| 評価 | 主Q＝分割適合性、4軸＝曖昧さ・追加解決見込み・重要性・コスト適合。高い追加解析価値を高品質と混同しない |
| 根拠 | 新測定を提供したら影響範囲の根拠新版。旧勝者も再評価し、異版の点数を比べない |
| 表示 | 元キーフレームだけへ重畳。主採用・手動閲覧・診断閲覧・旧根拠を分ける。模式図ではlane別アーキテクチャ、白ドット進行、queue待機数・混雑色を表示する |
| 証拠 | 実mask／実Jev／fixture／Replay／backend確定／UI適用を別記録。Jev高得点は正答の証明ではない |
| 保存 | 全候補・全run・失敗も保存対象。研究保存と一時cacheを分け、予算・期限を新chatで戻さない |
| 対象外 | OCR・VLM・同一個体対応・P2関係マップ・Jev後の追加認識・自動job剪定は後段 |

主Q、尺度・下限、候補固有測定／共通根拠の分離は正本に記載した設計案。モデル・SDK・測定設定・実行条件は基準固定前の未確定を残す。実装済みではない。

## 4．チャット履歴を増やさない引継ぎ

入口は、適用指示、上の短い共通境界、当該SCの詳細仕様、使用する公開型、最新の事実状態、必要ソースの索引だけにする。正本全体・過去の全会話・全報告を毎回読み直すことを既定にしない。

事実状態は20〜40行程度を目安とし、設計版、repo/branch/HEAD、残差分、完了・未完了、試験の件数と証拠位置、公開契約変更、profile・残予算、保存期限、次機能に影響する未決を記す。全文経緯を追記し続けず、次の依頼文も生成しない。

成功ログ・全DOM・全mask・大量JSONは証拠ファイルに保存し、会話には集計と該当参照を残す。失敗・矛盾・変更に必要な範囲だけ展開する。実画面検査・正常終了・安全境界の確認は省略しない。

一つの機能の試験と修正は同じチャットで閉じ、レビュー完了後に次機能の新チャットへ移る。途中継続が必要なら未完了理由・既試行を保存し、完了扱いにしない。分割数や特定のトークン削減率を最適化目標にはしない。

## 5．完成後の反復と追加分析

**同じ動画で構成を変えて再実行するたびに、新しいCodexチャットは必要ない。** 対応済みadapterの選択・設定・有限反復はアプリが担当する。

全runのmanifest・集計を対象にした比較は、必要なbatchが蓄積した時点で分析専用の新チャット`SR-<batch>`に分けられる。全runを索引・集計し、詳細画像は差・悪化・失敗・確認標本に絞る。新しい分析snapshotへ過去runを含める場合も、全ログの再投入は不要。

未対応backendの追加は、そのadapterと試験だけの`SA-<backend>`単位として別途設計できる。P2関係マップ・追加認識・自動剪定は本版の完成後の別計画。UI上でのスレッド数追加削除やアーキテクチャ自由編集は第一版へ入れない。これらの追加依頼文は現在作成しない。
